# Architecture

## Project Structure

```
src/
  lib/supabase/           Frontend-safe Supabase client (anon key only)
  auth/                   Auth provider, hooks, protected route wrapper
  config/env.ts           Fail-fast environment variable validation
  types/
    generated/            Auto-generated by `supabase gen types` — never hand-edited
    app/                  Handwritten domain types composed from generated types
  services/api/           Typed wrappers around Edge Function invocations

supabase/
  migrations/             SQL migrations (timestamp-named per Supabase CLI convention)
  functions/
    _shared/              Shared Edge Function utilities (admin client, CORS, errors, validation)
    v1/                   Versioned Edge Functions (v1/)
```

## Trust Boundary

```
┌──────────────────────────────┐     ┌──────────────────────────────┐
│         Browser              │     │     Supabase (Edge Functions) │
│                              │     │                              │
│  src/lib/supabase/client.ts  │     │  _shared/adminClient.ts       │
│  ── anon key only            │     │  ── service-role key          │
│  ── VITE_SUPABASE_ANON_KEY   │     │  ── SUPABASE_SERVICE_ROLE_KEY │
│  ── safe to bundle           │     │  ── NEVER bundled to browser  │
│                              │     │                              │
│  CANNOT import:              │     │  CANNOT be imported by:      │
│    SUPABASE_SERVICE_ROLE_KEY │     │    any src/ file              │
│    adminClient.ts            │     │                              │
└──────────────────────────────┘     └──────────────────────────────┘
```

## Key Rules

- `SUPABASE_SERVICE_ROLE_KEY` must never appear under `src/`
- All admin DB operations go through Edge Functions, never directly from the browser
- Environment validation crashes the app at boot on any missing var
